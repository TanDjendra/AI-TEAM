# AI Team Orchestrator - Release Checklist

Before deploying the AI Team Orchestrator V1 to production, ensure that all items on this checklist are satisfied. This guarantees that security boundaries, operational limits, and cost controls are functioning exactly as designed.

## 1. Prerequisites
- **Node.js**: v20.11 or higher.
- **Database**: PostgreSQL (or Supabase). *Note: The embedded PGlite is fine for local development but cannot scale to multiple concurrent worker processes.*
- **Model Router**: A valid, authorized `9Router` endpoint.
- **Environment**: Linux or Windows server capable of running background jobs (e.g. systemd, pm2, or Docker).

## 2. Environment Variables (.env)
Double check the `.env` configuration file in production. Ensure the following rules:
- `ROUTER_BASE_URL`: Must point to the internal API endpoint for `9Router`.
- `ROUTER_API_KEY`: Must be a production key with sufficient limits. Do NOT check this into source control.
- `DATABASE_URL`: Must be set for production persistence (e.g. `postgres://user:pass@host:5432/db`).
- `CODER_MODEL` and `REVIEWER_MODEL`: Must be set to `grip/deepseek-v4.1-flash` and `grip/gpt-5.6-luna`.
- `WORKER_CONCURRENCY`: Start with `1` or `2` to monitor initial load.
- `LOG_LEVEL`: Set to `info` for production.

## 3. Database Migration
Ensure the database schema is fully applied before starting the service:
```bash
npm run db:check
```
This command must return `ok: true`.

## 4. Startup Sequences
Always start the components in the following order:

### A. The Background Worker
The worker is responsible for running the background tasks and orchestration sweeps.
```bash
npm run worker
```
- Verify the worker logs indicate successful registration (`worker.registered`).
- Monitor that the initial stale sweep runs (`worker.startup_recovery`).

### B. The Dashboard (Next.js)
Start the frontend interface.
```bash
npm run build
npm start
```
- Verify the dashboard loads on the configured port.
- Navigate to the System Status page and ensure it connects to the database successfully.

## 5. Health Checks
- Check the orchestrator's connection to the Router and Models: `npm run router:check`
- Query the dashboard health endpoint: `GET /api/health`
- Verify worker registration: `GET /api/status`

## 6. Security Notes
- **Workspace Isolation**: Workspaces are isolated per task in the `workspaceRoot` directory. Avoid sharing this directory with sensitive system files.
- **Tool Policies**: The orchestrator enforces strict policies on command execution. Ensure the user running the Node process does not have elevated root/sudo privileges.
- **Secret Redaction**: The orchestrator attempts to redact API keys and secrets from model outputs and tool stderr/stdout, but production monitoring should still sanitize logs at the aggregator level.

## 7. Known Limitations & Operational Risks
- **PGlite Local Limitation**: The default `pglite` implementation operates with a single-file lock and will throw `Database is not reachable` if two processes (e.g., the Next.js server and the Worker) attempt to open it simultaneously. Production *must* use standard PostgreSQL.
- **Single-Process Harness**: Testing runs sequentially on the host machine. Long-running or infinitely looping unit tests may delay orchestration until the native timeout is triggered.
- **Agent Variability**: While structured parsing is strictly enforced, the GPT reviewer agent may occasionally interpret valid but complex code as needing low-severity fixes. The bounded review cycle (`MAX_REVIEW_CYCLES`) safely caps infinite loops, returning a `NEEDS_HUMAN` status.

## 8. Backup & Recovery Recommendation
- **Database Backup**: Standard PostgreSQL logical backups (`pg_dump`) run nightly.
- **Workspace State**: Code generated by the Orchestrator is transient until pushed to a Git remote. If a worker crashes mid-run, the database `runs` table will automatically flag the task as stale, and the `StaleSweeper` will transition it to `NEEDS_HUMAN`. No manual DB surgery is required.
- **Emergency Shutdown**: Send `SIGTERM` or `SIGINT` to the Node process. The worker node will safely interrupt running tasks and set its status to `STOPPED`.
